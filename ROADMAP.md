# Roadmap

A streaming 256-point complex FFT (with a programmable FIR still to come) on
the sky130 open PDK, generated by this repo's own Apache-2.0 generator and
taken toward DRC/LVS-clean GDS with klayout-tools and the open digital flow.

**Status as of 2026-11-13, `main` @ `2779bed`.** The live queue is
[`WORK_PLAN.md`](WORK_PLAN.md), the history [`WORK_LOG.md`](WORK_LOG.md), and
the T1 verdict of record
[`manifests/sky130-dsp-fft.signoff.json`](manifests/sky130-dsp-fft.signoff.json).

## Where it stands

On the README's maturity ladder: generated RTL bit-exact against the reference
model, on a placeholder growth schedule; the spec is still **proposed, not
ratified** ([`spec/spec.md`](spec/spec.md)). Evidenced on `main`:

- **Generator and RTL.** Own radix-2^2 SDF generator in `rtl/gen/` (decisions
  0001, 0004; #27, #29); `rtl/generated/` regenerated from
  `rtl/params/fft256.params`; valid/ready wrapper in `rtl/wrapper/` (PR #49).
- **Numerics.** Double-precision reference and bit-accurate fixed-point model
  in `sim/` (#16, #31); simulated SQNR minimum 65.65 dB over the spec's vector
  sets and zero overflow, on the placeholder schedule
  (`measurements/fft256-smoke.json`); no-overflow amplitude range in
  `measurements/overflow-range.json` (#56).
- **Verification.** cocotb bench checks the wrapper bit-exactly against the
  model under stalls, reset mid-frame and back-to-back frames, with negative
  controls (`make -C verification all`, PRs #51, #54, #57), run in CI.
- **Synthesis.** `klt synthesize` netlist
  `netlist/fft256_stream.sky130_fd_sc_hd.v` at `tt_025C_1v80`: 60715 cells,
  no macros, no latches (`synth/fft256.synth.report.json`). The report carries
  no STA (`sta: null`) and the request sets no clock constraint.

T1 checklist ([`manifests/design-evidence-tiers.md`](manifests/design-evidence-tiers.md),
tracker #5, whose own 2026-10-17 table is stale), from the verdict of record,
klt 0.8.0: **3 of 11 met**.

## Now

Startable today, independent of the layout decision; none has an issue yet.

1. **Growth-schedule study.** The spec's "Internal growth and scaling" row is
   an open target: `stage_widths=17..24`, `twiddle_width=16` is a placeholder
   and every SQNR and overflow figure rests on it. Done when a `sim/` sweep
   script with tests writes an append-only `measurements/schedule-sweep.json`
   giving, per candidate schedule, the per-set minimum SQNR, overflow counts
   and summed stage widths on the spec's vector sets. Blocks: nothing.
2. **Fallback and stretch sizes in the model.** The spec's FFT-size row says
   "64/1024 not run". Done when committed parameter files for 64 and 1024
   points exist and a recorded model run gives simulated SQNR and overflow for
   each on the spec's vector sets, labelled placeholder-schedule. Blocks:
   nothing (the generator accepts powers of 4).
3. **FIR source survey.** Every FIR row in the spec reads "target, no
   evidence: FIR source undecided", and the spec asks for a decision record
   first. Done when `spec/decisions/0005-*.md` exists with status Proposed:
   options (extend `rtl/gen/`, an external generator with licence checked,
   hand-written RTL), the verification cost of each, and a recommendation.
   The ruling is not part of the item. Blocks: nothing.
4. **README attestation pointer.** The README's Reproduce table names
   `manifests/item10-attestation-3.json`; the cited one is `-4`. Done when
   the README names the live attestation and, `README.md` being in the item 10
   inventory, a superseding inventory and attestation pass `signoff.yml`.

## Next

- **Select the schedule** (after Now 1): a decision record naming the chosen
  `stage_widths` / `twiddle_width` from the sweep, `rtl/params/fft256.params`
  updated, RTL and netlist regenerated, smoke and overflow records re-run.
  It changes the netlist that #17 routes, so sequence it before that re-run.
- **#17 place-and-route** (after the decision below): committed
  `layout/pnr_request.json` and run script, routed GDS with hash, P&R response
  with `power.pdn: true`, item 2 reads `met`.
- **#18, #19, #20** (after #17): one `klt` report each (DRC, LVS, ERC supply),
  cited in the manifest; items 3, 4 and 11 read `met`.
- **FIR model and RTL** (after the 0005 ruling): bit-accurate FIR model, then
  RTL and a cocotb coefficient-load test, per the spec's FIR and control rows.
- **Clock-constrained synthesis and pre-route timing**: `synth/fft256.synth.json`
  with `clock_period_ns` set and a `klt sta` report at the three signoff
  corners of decision 0003. The synthesis report says its STA extension is
  not in the published klayout-tools package: check `klt sta` at the pinned
  version first and file the gap upstream if it cannot run.

## Blocked and waiting

- **#17 (item 2, layout)** carries an operator decision. A first attempt at
  40 % utilisation finished floorplan, placement and CTS, but detailed routing
  of the ~60k-instance netlist did not finish in one session; no GDS. Options
  on the issue: retry with a lower-congestion floorplan (recommended there),
  run routing as a long or batch job, or fall back to 64 points. #18, #19 and
  #20 are blocked behind it.
- **#71** (remove the hand-rolled Yosys leg of `smoke-fft256`) carries an
  operator decision because it retires the evidence source for the spec's
  Storage row and touches attested files.
- **Spec ratification** waits on the reviews and ruling `spec/spec.md` names.

No open issue is labelled ready today; the four Now items are the
dispatchable work once filed.
