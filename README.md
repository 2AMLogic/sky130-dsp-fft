# sky130-dsp-fft

A streaming FFT engine with a programmable FIR filter on the
[SkyWater sky130](https://github.com/google/skywater-pdk) open PDK — RTL
produced by an open-source DSP generator, then taken toward DRC/LVS-clean
GDS by AI agents driving
[klayout-tools](https://github.com/2AMLogic/klayout-tools) and the
open-source digital flow: cocotb + Icarus for verification, Yosys for
synthesis, OpenROAD for place-and-route.

**Status: just opened, specification phase.** Nothing is designed yet.

**T1 status.** Graded by `klt signoff`, not restated here: see the verdict of
record [`manifests/sky130-dsp-fft.signoff.json`](manifests/sky130-dsp-fft.signoff.json)
and [`manifests/README.md`](manifests/README.md) for how it is regenerated.

**Built agent-native.** Every specification, decision record, testbench, and
line of documentation here is produced by AI agents working from a ratified
spec and an append-only evidence trail — not human-authored work that agents
merely assisted with. Verification is the product: every claim traces to a
recorded result. Where the agents hit friction with the open-source tooling —
most often [klayout-tools](https://github.com/2AMLogic/klayout-tools) — that
friction is filed as a public issue against the tool itself, so the fix
benefits everyone using sky130, not just this repo.

## Why this block, on this node

The fleet's digital canaries so far are hand-written RTL. This one is
**generated**: the FFT and FIR datapaths come out of an open generator from
a parameter set, and the repo's work is everything around that — choosing
the generator, pinning it so the RTL can be regenerated byte-for-byte,
proving the fixed-point numerics against a floating-point reference, and
closing a multiplier-heavy datapath on a standard-cell library with no
hard multipliers.

That tests a different seam of the flow than the siblings do. A generator
that emits a deep pipeline of constant and variable multipliers stresses
synthesis, placement density and timing in ways a control-dominated block
does not, and "the RTL is generated" moves the provenance question from
"who wrote this line" to "which generator, at which commit, with which
parameters".

## Scope

- **In scope**: generator selection and pinning; a streaming complex FFT;
  a programmable FIR; fixed-point scaling; a bit-accurate reference model;
  physical implementation on sky130.
- **Not in scope**: hand-redesigning the generator's datapath. Where the
  generator is wrong or missing a capability, file it upstream on the
  generator's own tracker and record the workaround here.
- **Memory**: v1 uses register/flop storage. Compiled SRAM macros are a
  later spec change, not a v1 dependency.

## Target specification (DRAFT — full proposed spec in [`spec/spec.md`](spec/spec.md), awaiting ratification)

| Parameter | Target | Fallback | Stretch |
|---|---|---|---|
| FFT size | 256-point complex | 64-point | 1024-point, or runtime-selectable size |
| Architecture | streaming pipeline, 1 sample/clock | — | — |
| Input / output | 16-bit I + 16-bit Q fixed point | 12-bit | 18-bit |
| Accuracy | SQNR ≥ 60 dB vs. double-precision reference | ≥ 40 dB | ≥ 70 dB |
| FIR | 32-tap, 16-bit programmable coefficients | 16-tap | 64-tap or decimating |
| Clock (signoff corners `ss_100C_1v60`, `tt_025C_1v80`, `ff_n40C_1v95`; all 16 reported) | 50 MHz | 25 MHz | 100 MHz |
| Signoff | DRC + LVS clean | — | — |

SQNR is computed in simulation on a stated vector set (random and tone
inputs at stated amplitudes) against the reference model. It is a simulated
figure.

Maturity ladder: generator chosen and pinned → spec ratified → generated
RTL bit-exact against the reference model → numerics meet the SQNR target
→ layout DRC/LVS-clean → timing closed across corners → shuttle seat →
measured silicon. **Current position: pre-spec.**

## Repo layout

```
spec/          ratified spec + decision records (generator choice first)
rtl/           generated RTL + the pinned generator invocation that produced it
verification/  cocotb testbenches against the reference model
sim/           numerics: reference model, SQNR sweeps, scaling studies
layout/        GDS + DRC/LVS reports (klayout-tools driven)
measurements/  silicon characterization (empty until tape-out)
```

## Reproduce

Every committed result, the command that reproduces it, and what it needs.
Run from the repository root. Toolchain pins and the full cold start are in
[`verification/README.md`](verification/README.md); they are not repeated here.

| Result | Command | Prerequisites |
|---|---|---|
| RTL lint, simulation and negative control (placeholder module) | `make -C verification all` | `python3 -m venv .venv && .venv/bin/pip install -r verification/requirements.txt`; Icarus Verilog, Verilator and Yosys at the versions in `verification/toolchain.json` (`all` runs `check-tools` first) |
| `measurements/synth-placeholder.json` (Yosys smoke synthesis) | `make -C verification synth` | as above, plus the sky130 PDK at the pinned `ciel` revision under `PDK_ROOT` (default `~/.ciel`); local only, not run in CI |
| Tier verdict of record `manifests/sky130-dsp-fft.signoff.json` | the `klt signoff --manifest` command in [`manifests/README.md`](manifests/README.md#regenerate) | `uvx` and `klayout-tools==0.8.0` |
| Item 10 attestation `manifests/item10-attestation.json` | the `klt signoff --attest 10` command in [`manifests/README.md`](manifests/README.md#regenerate) | as above; the `local_only` checks need the verification toolchain |

CI re-checks the signoff record and the item 10 attestation
(`.github/workflows/signoff.yml`) and runs lint, simulation and the negative
control (`.github/workflows/rtl-ci.yml`).
